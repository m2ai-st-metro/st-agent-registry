## 1. Reference Architecture for a Tier 1 Agent

### 1.1 What Makes a Tier 1 Agent

A Tier 1 agent is a **fully autonomous agent** built on the Claude Agent SDK (Python). It:

- Runs as a standalone process or subprocess
- Has its own system prompt derived from a persona YAML
- Registers tool groups via `allowed_tools` and MCP servers
- Implements guardrails via the SDK hook system (`PreToolUse`, `PostToolUse`, `SubagentStop`)
- Can delegate to sub-agents via the `Task` tool
- Persists learned patterns across sessions via `.codebase_learnings.json` or equivalent
- Operates within defined persona boundaries enforced by validation hooks

### 1.2 Directory Structure

Each Tier 1 agent lives inside the Academy's `personas/` tree and adds a `agent/` subdirectory containing the runtime implementation:

```
personas/
  code-reviewer/
    persona.yaml                 # Persona definition (identity, voice, frameworks, agent_config)
    README.md                    # Persona documentation
    agent/                       # Tier 1 runtime (Python, generated by CLI)
      __init__.py
      main.py                    # Entry point: creates ClaudeSDKClient, runs agent loop
      config.py                  # Loads persona YAML, resolves tool groups, builds ClaudeAgentOptions
      hooks.py                   # Guardrail hooks (PreToolUse, PostToolUse, persona boundary enforcement)
      tools.py                   # Custom in-process tools via @tool decorator + create_sdk_mcp_server
      memory.py                  # Session memory: load/save learnings, format for prompt injection
      prompts/
        system_prompt.md         # Generated system prompt (from persona YAML via generateSystemPrompt)
        task_templates/          # Pre-built task prompts for common use cases
          review_pr.md
          review_file.md
      tests/
        test_hooks.py            # Unit tests for guardrail hooks
        test_config.py           # Tests for config loading and tool resolution
      requirements.txt           # Python dependencies (claude-agent-sdk, python-dotenv)
    frameworks/                  # External framework YAML files (existing convention)
    case-studies/                # External case study YAML files (existing convention)
```

### 1.3 Entry Point (`main.py`)

The entry point creates a `ClaudeSDKClient`, configures it from the persona YAML, and runs the agent loop.

```python
"""
Code Reviewer Agent -- Tier 1 Autonomous Agent
================================================

Entry point for the code-reviewer agent built on Claude Agent SDK.
Configuration derived from persona.yaml via the Academy config loader.
"""

import asyncio
import sys
from pathlib import Path

from dotenv import load_dotenv

# Load shared credentials
load_dotenv(Path.home() / ".env.shared")
load_dotenv()

from claude_agent_sdk import (
    AssistantMessage,
    ClaudeSDKClient,
    ClaudeAgentOptions,
    ResultMessage,
    TextBlock,
    ToolUseBlock,
)

from config import build_agent_options
from memory import load_learnings, format_learnings_for_prompt


async def run_agent(task: str, project_dir: Path) -> str:
    """
    Run the agent with a specific task.

    Args:
        task: The task prompt (e.g., "Review the PR at #42")
        project_dir: Working directory for file operations

    Returns:
        Agent's final response text
    """
    # Build options from persona.yaml + runtime context
    options = build_agent_options(
        project_dir=project_dir,
        extra_context=format_learnings_for_prompt(
            load_learnings(project_dir)
        ),
    )

    response_text = ""

    async with ClaudeSDKClient(options=options) as client:
        await client.query(task)

        async for msg in client.receive_response():
            if isinstance(msg, AssistantMessage):
                for block in msg.content:
                    if isinstance(block, TextBlock):
                        response_text += block.text
                        print(block.text, end="", flush=True)
                    elif isinstance(block, ToolUseBlock):
                        print(f"\n[Tool: {block.name}]", flush=True)
            elif isinstance(msg, ResultMessage):
                if hasattr(msg, "result"):
                    print(f"\n{msg.result}")

    return response_text


async def main() -> int:
    """CLI entry point."""
    if len(sys.argv) < 2:
        print("Usage: python -m agent <task> [--project-dir <path>]")
        return 1

    task = sys.argv[1]
    project_dir = Path(sys.argv[3] if len(sys.argv) > 3 else ".")

    try:
        await run_agent(task, project_dir)
        return 0
    except KeyboardInterrupt:
        print("\nInterrupted")
        return 130
    except Exception as e:
        print(f"\nError: {type(e).__name__}: {e}")
        return 1


if __name__ == "__main__":
    sys.exit(asyncio.run(main()))
```

### 1.4 Configuration Loader (`config.py`)

Loads the persona YAML, resolves tool groups, and builds `ClaudeAgentOptions`:

```python
"""
Agent Configuration Loader
===========================

Reads persona.yaml and builds ClaudeAgentOptions for the Claude Agent SDK.
Tool groups are resolved from the standard catalog. Hooks are loaded from
the guardrails module.
"""

from pathlib import Path
from typing import Any, cast

import yaml

from claude_agent_sdk import ClaudeAgentOptions, HookMatcher
from claude_agent_sdk.types import HookCallback

from hooks import (
    persona_boundary_hook,
    bash_security_hook,
    read_only_enforcement_hook,
)

# Standard tool group catalog -- shared across all Academy agents
TOOL_GROUPS: dict[str, list[str]] = {
    "file_read": ["Read", "Glob", "Grep"],
    "file_write": ["Read", "Write", "Edit", "Glob", "Grep"],
    "bash": ["Bash"],
    "web": ["WebSearch", "WebFetch"],
    "code_review": ["Read", "Glob", "Grep", "Bash"],
    "coding": ["Read", "Write", "Edit", "Glob", "Grep", "Bash"],
    "research": ["Read", "Glob", "Grep", "WebSearch", "WebFetch"],
    "deployment": ["Read", "Glob", "Grep", "Bash"],
    "content": ["Read", "Write", "Edit", "Glob", "Grep", "WebSearch", "WebFetch"],
    "linear": [],   # Populated at runtime from Arcade MCP tools
    "github": [],   # Populated at runtime from Arcade MCP tools
    "slack": [],    # Populated at runtime from Arcade MCP tools
}

# Model name mapping: short name -> full model ID
MODEL_MAP: dict[str, str] = {
    "haiku": "claude-haiku-4-5-20251001",
    "sonnet": "claude-sonnet-4-5-20250514",
    "opus": "claude-opus-4-20250514",
}

AGENT_DIR = Path(__file__).parent
PERSONA_DIR = AGENT_DIR.parent
PERSONA_YAML = PERSONA_DIR / "persona.yaml"


def load_persona_config() -> dict[str, Any]:
    """Load and parse persona.yaml."""
    with open(PERSONA_YAML) as f:
        return yaml.safe_load(f)


def resolve_tools(agent_config: dict[str, Any]) -> list[str]:
    """
    Resolve tool groups + additional - exclude into a flat tool list.

    Reads from agent_config.tools:
      - groups: list of tool group names from TOOL_GROUPS
      - additional: extra individual tool names
      - exclude: tool names to remove from the resolved set
    """
    tools_config = agent_config.get("tools", {})
    groups = tools_config.get("groups", [])
    additional = tools_config.get("additional", [])
    exclude = set(tools_config.get("exclude", []))

    # Resolve groups into flat list
    resolved: list[str] = []
    for group_name in groups:
        group_tools = TOOL_GROUPS.get(group_name, [])
        if not group_tools:
            print(f"Warning: Unknown tool group '{group_name}'")
        resolved.extend(group_tools)

    # Add individual tools
    resolved.extend(additional)

    # Remove excluded tools and deduplicate while preserving order
    seen: set[str] = set()
    final: list[str] = []
    for tool in resolved:
        if tool not in exclude and tool not in seen:
            seen.add(tool)
            final.append(tool)

    return final


def resolve_model(agent_config: dict[str, Any], default: str = "sonnet") -> str:
    """Resolve model short name to full model ID."""
    model_name = agent_config.get("model", default)
    return MODEL_MAP.get(model_name, model_name)


def load_system_prompt(agent_config: dict[str, Any], extra_context: str = "") -> str:
    """
    Load the system prompt from file or generate from persona YAML.

    Priority:
    1. agent_config.prompt_file (explicit prompt file path)
    2. prompts/system_prompt.md (convention-based)
    3. Auto-generated from persona YAML identity + voice + frameworks
    """
    # Try explicit prompt file
    prompt_file = agent_config.get("prompt_file")
    if prompt_file:
        prompt_path = AGENT_DIR / "prompts" / prompt_file
        if prompt_path.exists():
            prompt = prompt_path.read_text()
            if extra_context:
                prompt += f"\n\n{extra_context}"
            return prompt

    # Try convention-based prompt
    default_prompt = AGENT_DIR / "prompts" / "system_prompt.md"
    if default_prompt.exists():
        prompt = default_prompt.read_text()
        if extra_context:
            prompt += f"\n\n{extra_context}"
        return prompt

    # Fall back to auto-generation from persona YAML
    persona = load_persona_config()
    identity = persona.get("identity", {})
    voice = persona.get("voice", {})

    sections = [
        f"# {identity.get('name', 'Agent')}",
        f"\n{identity.get('role', '')}",
        f"\n{identity.get('background', '')}",
        f"\n## Communication Style",
        f"\nTone: {', '.join(voice.get('tone', []))}",
        f"\nConstraints: {', '.join(voice.get('constraints', []))}",
    ]

    prompt = "\n".join(sections)
    if extra_context:
        prompt += f"\n\n{extra_context}"
    return prompt


def build_default_hooks(
    agent_config: dict[str, Any],
) -> dict[str, list[HookMatcher]]:
    """
    Build hook configuration based on agent_config.guardrails.

    All Tier 1 agents get:
    - PreToolUse: bash security hook (command allowlist)
    - PostToolUse on Task: persona boundary validation

    Read-only agents additionally get:
    - PreToolUse on Write|Edit: deny file modifications
    """
    hooks: dict[str, list[HookMatcher]] = {
        "PreToolUse": [
            HookMatcher(
                matcher="Bash",
                hooks=[cast(HookCallback, bash_security_hook)],
            ),
        ],
        "PostToolUse": [
            HookMatcher(
                matcher="Task",
                hooks=[cast(HookCallback, persona_boundary_hook)],
            ),
        ],
    }

    # Read-only enforcement for agents without write tools
    guardrails = agent_config.get("guardrails", {})
    if guardrails.get("read_only", False):
        hooks["PreToolUse"].append(
            HookMatcher(
                matcher="Write|Edit",
                hooks=[cast(HookCallback, read_only_enforcement_hook)],
            )
        )

    return hooks


def build_agent_options(
    project_dir: Path,
    extra_context: str = "",
) -> ClaudeAgentOptions:
    """
    Build complete ClaudeAgentOptions from persona.yaml.

    Args:
        project_dir: Working directory for file operations
        extra_context: Additional context to append to system prompt
            (e.g., codebase learnings, session history)

    Returns:
        Fully configured ClaudeAgentOptions ready for ClaudeSDKClient
    """
    persona = load_persona_config()
    agent_config = persona.get("agent_config", {})

    tools = resolve_tools(agent_config)
    model = resolve_model(agent_config)
    system_prompt = load_system_prompt(agent_config, extra_context)
    hooks = build_default_hooks(agent_config)

    # Build subagent definitions if specified
    subagents = _build_subagent_definitions(agent_config)

    # Add Task tool if subagents are defined
    if subagents and "Task" not in tools:
        tools.append("Task")

    return ClaudeAgentOptions(
        model=model,
        system_prompt=system_prompt,
        allowed_tools=tools,
        hooks=hooks,
        agents=subagents if subagents else None,
        max_turns=agent_config.get("max_turns", 200),
        cwd=str(project_dir.resolve()),
    )


def _build_subagent_definitions(
    agent_config: dict[str, Any],
) -> dict[str, Any] | None:
    """Build AgentDefinition dict from agent_config.subagents if present."""
    from claude_agent_sdk import AgentDefinition

    subagents_config = agent_config.get("subagents", {})
    if not subagents_config:
        return None

    definitions: dict[str, AgentDefinition] = {}
    for name, sub_config in subagents_config.items():
        definitions[name] = AgentDefinition(
            description=sub_config["description"],
            prompt=sub_config.get("prompt", ""),
            tools=resolve_tools(sub_config) if sub_config.get("tools") else None,
            model=sub_config.get("model"),
        )

    return definitions
```

### 1.5 Guardrail Hooks (`hooks.py`)

Hooks implement safety constraints using the SDK's hook system:

```python
"""
Guardrail Hooks for Tier 1 Agents
==================================

Pre/Post tool-use hooks that enforce:
1. Bash command allowlisting (defense in depth)
2. Persona boundary validation (read-only agents don't write files)
3. Custom domain-specific guardrails
"""

import shlex
from typing import Any

from claude_agent_sdk import PreToolUseHookInput
from claude_agent_sdk.types import HookContext, SyncHookJSONOutput


# Default allowed bash commands for all Tier 1 agents
DEFAULT_ALLOWED_COMMANDS: set[str] = {
    "ls", "cat", "head", "tail", "wc", "grep", "find",
    "pwd", "echo", "which",
    "python", "python3",
    "npm", "npx", "node",
    "git",
    "curl",
}


async def bash_security_hook(
    input_data: PreToolUseHookInput,
    tool_use_id: str | None = None,
    context: HookContext | None = None,
) -> SyncHookJSONOutput:
    """
    Pre-tool-use hook that validates bash commands against an allowlist.

    Returns empty dict to allow, or dict with decision='deny' to block.
    """
    if input_data.get("tool_name") != "Bash":
        return {}

    command: str = input_data.get("tool_input", {}).get("command", "")
    if not command:
        return {}

    try:
        tokens = shlex.split(command)
    except ValueError:
        return SyncHookJSONOutput(
            hookSpecificOutput={
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": f"Could not parse command: {command}",
            }
        )

    if tokens and tokens[0] not in DEFAULT_ALLOWED_COMMANDS:
        return SyncHookJSONOutput(
            hookSpecificOutput={
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": (
                    f"Command '{tokens[0]}' not in allowed list. "
                    f"Allowed: {sorted(DEFAULT_ALLOWED_COMMANDS)}"
                ),
            }
        )

    return {}


async def read_only_enforcement_hook(
    input_data: PreToolUseHookInput,
    tool_use_id: str | None = None,
    context: HookContext | None = None,
) -> SyncHookJSONOutput:
    """
    Pre-tool-use hook that blocks Write and Edit tools for read-only agents.
    """
    tool_name = input_data.get("tool_name", "")
    if tool_name in ("Write", "Edit"):
        return SyncHookJSONOutput(
            hookSpecificOutput={
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": (
                    f"This agent is read-only. {tool_name} is not permitted. "
                    "Report findings without modifying files."
                ),
            }
        )
    return {}


async def persona_boundary_hook(
    input_data: dict[str, Any],
    tool_use_id: str | None = None,
    context: HookContext | None = None,
) -> SyncHookJSONOutput:
    """
    Post-tool-use hook on Task tool that validates subagent output
    stays within persona boundaries.

    Checks that read-only subagents haven't reported file modifications.
    """
    if input_data.get("tool_name") != "Task":
        return {}

    response = str(input_data.get("tool_response", "")).lower()
    tool_input = input_data.get("tool_input", {})
    agent_type = tool_input.get("subagent_type", "")

    # Define read-only agent types
    read_only_agents = {"qa", "code_review", "analyzer", "auditor"}

    if agent_type in read_only_agents:
        write_indicators = ["wrote file", "created file", "edited file", "modified file"]
        violations = [ind for ind in write_indicators if ind in response]

        if violations:
            context_msg = (
                f"PERSONA VIOLATION: {agent_type} agent appears to have "
                f"modified files (detected: {', '.join(violations)}). "
                "This agent should be read-only."
            )
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PostToolUse",
                    "additionalContext": context_msg,
                }
            }

    return {}
```

### 1.6 Memory Pattern (`memory.py`)

Session memory persists learnings across invocations:

```python
"""
Agent Memory -- Persistent Learning Across Sessions
=====================================================

Implements the compound learning pattern from yce-harness:
- Loads .codebase_learnings.json from the project directory
- Formats learnings as prompt context for the agent
- Saves new learnings discovered during the session

This is the same pattern used by the coding and code_review agents
in yce-harness, ensuring consistency across the ST Metro ecosystem.
"""

import json
from pathlib import Path
from typing import Any

LEARNINGS_FILENAME = ".codebase_learnings.json"

DEFAULT_LEARNINGS: dict[str, Any] = {
    "codebase_patterns": {
        "framework": "",
        "styling": "",
        "state_management": "",
        "file_structure": "",
    },
    "common_mistakes": [],
    "effective_patterns": [],
    "review_findings": [],
}


def load_learnings(project_dir: Path) -> dict[str, Any]:
    """Load learnings from project directory, or return defaults."""
    learnings_file = project_dir / LEARNINGS_FILENAME
    if not learnings_file.exists():
        return json.loads(json.dumps(DEFAULT_LEARNINGS))

    try:
        with open(learnings_file) as f:
            data = json.load(f)
        for key, default_value in DEFAULT_LEARNINGS.items():
            if key not in data:
                data[key] = (
                    json.loads(json.dumps(default_value))
                    if isinstance(default_value, (dict, list))
                    else default_value
                )
        return data
    except (json.JSONDecodeError, IOError):
        return json.loads(json.dumps(DEFAULT_LEARNINGS))


def save_learnings(project_dir: Path, learnings: dict[str, Any]) -> None:
    """Persist learnings to project directory."""
    learnings_file = project_dir / LEARNINGS_FILENAME
    project_dir.mkdir(parents=True, exist_ok=True)
    with open(learnings_file, "w") as f:
        json.dump(learnings, f, indent=2)


def format_learnings_for_prompt(learnings: dict[str, Any]) -> str:
    """Format learnings as markdown for system prompt injection."""
    sections: list[str] = []

    patterns = learnings.get("codebase_patterns", {})
    pattern_lines = [f"- **{k}**: {v}" for k, v in patterns.items() if v]
    if pattern_lines:
        sections.append("### Codebase Patterns\n" + "\n".join(pattern_lines))

    mistakes = learnings.get("common_mistakes", [])
    if mistakes:
        lines = [
            f"- {m.get('issue', 'Unknown')} -> {m.get('fix', 'No fix recorded')}"
            for m in mistakes[-5:]
        ]
        sections.append("### Common Mistakes to Avoid\n" + "\n".join(lines))

    effective = learnings.get("effective_patterns", [])
    if effective:
        lines = [
            f"- {p.get('pattern', 'Unknown')} (confidence: {p.get('confidence', '?')})"
            for p in effective[-5:]
        ]
        sections.append("### Effective Patterns\n" + "\n".join(lines))

    if not sections:
        return ""

    return "## CODEBASE CONTEXT (from past sessions)\n\n" + "\n\n".join(sections)
```

### 1.7 Custom Tools (`tools.py`)

For agents that need domain-specific tools beyond the built-in set:

```python
"""
Custom In-Process Tools
========================

Uses the SDK's @tool decorator and create_sdk_mcp_server to register
custom tools that run in the same Python process as the agent.

These tools are specific to this agent's domain. General-purpose tools
(file ops, bash, web) come from the SDK's built-in tools.
"""

from claude_agent_sdk import tool, create_sdk_mcp_server


@tool(
    name="get_review_checklist",
    description="Get a structured review checklist for a specific file type",
    input_schema={"file_extension": str},
)
async def get_review_checklist(args: dict) -> dict:
    """Return a review checklist based on file type."""
    ext = args.get("file_extension", "").lower()

    checklists = {
        ".py": [
            "Type hints on function signatures",
            "Docstrings on public functions",
            "Error handling at boundaries",
            "No bare except clauses",
            "Imports organized (stdlib, third-party, local)",
        ],
        ".ts": [
            "Strict TypeScript types (no 'any')",
            "ESM imports with .js extensions",
            "Error boundaries in components",
            "Proper null/undefined handling",
        ],
        ".sql": [
            "Parameterized queries (no string interpolation)",
            "Index considerations for WHERE clauses",
            "Transaction boundaries",
            "Rollback safety",
        ],
    }

    checklist = checklists.get(ext, ["General code quality review"])

    return {
        "content": [
            {"type": "text", "text": "\n".join(f"- [ ] {item}" for item in checklist)}
        ]
    }


def create_agent_tools_server():
    """Create an in-process MCP server with this agent's custom tools."""
    return create_sdk_mcp_server(
        name="agent-tools",
        version="1.0.0",
        tools=[get_review_checklist],
    )
```

## 2. How the Academy Scaffolds a New Tier 1 Agent

### 2.1 CLI Command Extension

The existing `persona-academy create` command (in `src/cli/commands/create.ts`) scaffolds a Tier 3 persona today. For Tier 1, the CLI adds a `--tier` flag:

```bash
# Scaffold a Tier 3 persona (current behavior, default)
persona-academy create my-analyst

# Scaffold a Tier 1 agent (new)
persona-academy create my-analyst --tier 1

# Scaffold a Tier 2 MCP server (new)
persona-academy create my-analyst --tier 2
```

### 2.2 What `--tier 1` Generates

When `--tier 1` is specified, the CLI generates the full `agent/` subdirectory alongside the persona YAML:

```
personas/my-analyst/
  persona.yaml           # Standard persona YAML + agent_config section
  README.md              # Updated with Tier 1 usage instructions
  agent/
    __init__.py          # Package init
    main.py              # Entry point (from template, ready to run)
    config.py            # Config loader (from template, imports shared catalog)
    hooks.py             # Guardrail hooks (pre-populated based on tool groups)
    tools.py             # Custom tools stub (empty, developer fills in)
    memory.py            # Memory pattern (from template, ready to use)
    prompts/
      system_prompt.md   # Auto-generated from persona YAML
    tests/
      test_hooks.py      # Test stubs for guardrail hooks
      test_config.py     # Test stubs for config loading
    requirements.txt     # claude-agent-sdk, python-dotenv, pyyaml
```

### 2.3 What Gets Auto-Configured from Persona YAML

| Persona YAML Field | Agent Runtime Mapping |
|---|---|
| `identity.name` | System prompt header, agent display name |
| `identity.role` | System prompt role line |
| `identity.background` | System prompt context section |
| `voice.tone` | System prompt "Communication Style" section |
| `voice.phrases` | System prompt "Characteristic Phrases" section |
| `voice.style` | System prompt "Approach" section |
| `voice.constraints` | System prompt constraints AND guardrail hook logic |
| `frameworks.*` | System prompt "Analytical Frameworks" section |
| `case_studies.*` | System prompt "Reference Cases" section |
| `agent_config.description` | `AgentDefinition.description` (for orchestrator routing) |
| `agent_config.prompt_file` | Path to system prompt markdown file |
| `agent_config.model` | `ClaudeAgentOptions.model` (resolved via MODEL_MAP) |
| `agent_config.tools.groups` | `ClaudeAgentOptions.allowed_tools` (resolved via TOOL_GROUPS) |
| `agent_config.tools.additional` | Extra tools appended to resolved set |
| `agent_config.tools.exclude` | Tools removed from resolved set |
| `agent_config.guardrails` | Hook configuration (read_only, allowed_commands, etc.) |
| `agent_config.max_turns` | `ClaudeAgentOptions.max_turns` |
| `agent_config.subagents` | `ClaudeAgentOptions.agents` (AgentDefinition dict) |
| `validation.must_include` | Not used at runtime -- used for persona fidelity testing |
| `validation.must_avoid` | Can be cross-referenced by guardrail hooks |

### 2.4 What the Developer Fills In

After scaffolding, the developer customizes:

1. **`tools.py`**: Add domain-specific custom tools using the `@tool` decorator
2. **`hooks.py`**: Extend guardrail hooks with domain-specific safety rules
3. **`prompts/system_prompt.md`**: Refine the auto-generated prompt with domain expertise
4. **`prompts/task_templates/`**: Add pre-built task prompts for common use cases
5. **`agent_config.subagents`**: Define sub-agents if the agent needs to delegate
6. **`tests/`**: Write actual test cases for hooks and configuration

### 2.5 Persona YAML with Full agent_config (Example)

```yaml
# Code Reviewer -- Tier 1 Agent Configuration
agent_config:
  description: >-
    Reviews code for security vulnerabilities, architecture patterns,
```

## 3. Agent Handoff Patterns

### 3.1 Orchestrator-to-Subagent (Primary Pattern)

This is the standard delegation pattern used by yce-harness and supported natively by the SDK. The orchestrator agent delegates to specialized sub-agents via the `Task` tool.

```
Orchestrator (Haiku/Sonnet)
  |
  +-- Task tool --> Linear Agent (Haiku)
  |                   tools: [Linear MCP tools, Read, Glob]
  |
  +-- Task tool --> Coding Agent (Sonnet)
  |                   tools: [Read, Write, Edit, Bash, Playwright]
  |
  +-- Task tool --> Code Review Agent (Sonnet)
  |                   tools: [Read, Glob, Grep, Bash]
  |
  +-- Task tool --> GitHub Agent (Haiku)
  |                   tools: [GitHub MCP tools, Bash, Read]
  |
  +-- Task tool --> Slack Agent (Haiku)
                      tools: [Slack MCP tools, Read]
```

**Key constraint from the SDK**: Subagents cannot spawn their own subagents. Do NOT include `Task` in a subagent's tools array. This means delegation is single-depth only.

**Implementation** (from yce-harness `agents/definitions.py`):

```python
from claude_agent_sdk import AgentDefinition

AGENT_DEFINITIONS = {
    "code_review": AgentDefinition(
        description=(
            "Reviews code for security vulnerabilities, architecture patterns, "
            "and quality issues. Use AFTER implementation and BEFORE committing."
        ),
        prompt=load_prompt("code_review_agent_prompt"),
        tools=["Read", "Glob", "Grep", "Bash"],
        model="sonnet",
    ),
}
```

### 3.2 Parallel Subagent Execution

Claude can invoke multiple subagents concurrently for independent tasks. The SDK handles parallelization automatically when the orchestrator issues multiple Task tool calls in the same turn.

```
Orchestrator
  |
  +-- Task (parallel) --> style-checker (Haiku)
  +-- Task (parallel) --> security-scanner (Sonnet)
  +-- Task (parallel) --> test-coverage (Haiku)
  |
  <-- Aggregated results from all three
```

### 3.3 Human-in-the-Loop Escalation

For decisions that require human judgment, the agent uses the `AskUserQuestion` tool (built into the SDK) or a custom HIL gate:

```python
# Option 1: Use built-in AskUserQuestion tool
# Add "AskUserQuestion" to allowed_tools
# Claude will use it when it needs human input

# Option 2: Custom HIL via hooks
async def hil_gate_hook(input_data, tool_use_id, context):
    """Require human approval for specific operations."""
    tool_name = input_data.get("tool_name", "")
    tool_input = input_data.get("tool_input", {})

    # Require approval for destructive operations
    if tool_name == "Bash":
        command = tool_input.get("command", "")
        if any(cmd in command for cmd in ["rm", "drop", "delete", "truncate"]):
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PreToolUse",
                    "permissionDecision": "ask",
                    "permissionDecisionReason": (
                        f"Destructive command detected: {command[:100]}. "
                        "Requires human approval."
                    ),
                }
            }
    return {}
```

### 3.4 Agent-to-Agent Communication (via Orchestrator)

Since subagents cannot call other subagents directly, cross-agent communication goes through the orchestrator:

```
1. Orchestrator delegates "implement feature X" to Coding Agent
2. Coding Agent returns implementation
3. Orchestrator delegates "review the implementation" to Code Review Agent
4. Code Review Agent returns findings
5. Orchestrator delegates "fix the issues" to Coding Agent
6. Repeat until quality gate passes
```

The orchestrator's system prompt defines this workflow:

```markdown
## Workflow

1. Read project state (Linear issues, git status)
2. Delegate implementation to **coding** agent
3. After implementation, delegate review to **code_review** agent
4. If review finds blockers, delegate fixes to **coding** agent
5. When review passes, delegate commit/PR to **github** agent
6. Send completion notification via **slack** agent
```

### 3.5 Session Resumption

Subagents can be resumed to continue where they left off. The SDK persists subagent transcripts independently of the main conversation:

```python
# Capture agent_id from Task tool result
# Resume with: query(prompt=f"Resume agent {agent_id} ...", options=ClaudeAgentOptions(resume=session_id))
```

## 4. Tool Group Catalog

Tool groups are named collections that Tier 1 agents compose from. Each group maps to a list of tool names recognized by the Claude Agent SDK.

### 4.1 Standard Tool Groups

| Group Name | Tools | Use Case | Read-Only |
|---|---|---|---|
| `file_read` | `Read`, `Glob`, `Grep` | Read files, search patterns | Yes |
| `file_write` | `Read`, `Write`, `Edit`, `Glob`, `Grep` | Full file operations | No |
| `bash` | `Bash` | Shell command execution | No |
| `web` | `WebSearch`, `WebFetch` | Internet access | Yes |
| `code_review` | `Read`, `Glob`, `Grep`, `Bash` | Static analysis, linting | Yes (Bash for linters) |
| `coding` | `Read`, `Write`, `Edit`, `Glob`, `Grep`, `Bash` | Full development | No |
| `research` | `Read`, `Glob`, `Grep`, `WebSearch`, `WebFetch` | Research and analysis | Yes |
| `deployment` | `Read`, `Glob`, `Grep`, `Bash` | Build, deploy, infra | No |
| `content` | `Read`, `Write`, `Edit`, `Glob`, `Grep`, `WebSearch`, `WebFetch` | Content creation | No |
| `testing` | `Read`, `Glob`, `Grep`, `Bash` | Test execution, analysis | Read + Execute |
| `browser` | Playwright MCP tools (8 tools) | Browser automation | No |

### 4.2 External Service Tool Groups (via MCP)

| Group Name | Tools (MCP) | Provider |
|---|---|---|
| `linear` | 39 Linear MCP tools | Arcade MCP Gateway |
| `github` | 46 GitHub MCP tools | Arcade MCP Gateway |
| `slack` | 8 Slack MCP tools | Arcade MCP Gateway |
| `browser` | 8 Playwright MCP tools | @playwright/mcp |

### 4.3 Composition Rules

1. **Groups are additive**: `groups: ["file_read", "bash"]` produces `["Read", "Glob", "Grep", "Bash"]`
2. **Deduplication**: If multiple groups include the same tool, it appears once
3. **`additional` adds**: Individual tools not in any group can be added: `additional: ["AskUserQuestion"]`
4. **`exclude` removes**: Remove specific tools from the resolved set: `exclude: ["Bash"]`
5. **`Task` auto-added**: If `subagents` are defined, `Task` is automatically added to the tool list
6. **MCP tool naming**: MCP tools follow `mcp__<server>__<action>` format

### 4.4 How Tool Groups Are Defined

Tool groups live in a shared Python module imported by all Tier 1 agents. This is the single source of truth:

## 5. Guardrail Templates

### 5.1 Default Guardrails (All Tier 1 Agents)

Every Tier 1 agent ships with these guardrails by default:

| Guardrail | Hook Type | Matcher | Behavior |
|---|---|---|---|
| Bash command allowlist | `PreToolUse` | `Bash` | Only commands in `allowed_commands` can execute |
| Persona boundary check | `PostToolUse` | `Task` | Validates subagent output matches role constraints |
| Max file size | `PreToolUse` | `Read` | Prevents reading excessively large files |

### 5.2 Read-Only Guardrail

For agents that should never modify files (code_review, qa, analyzer):

```yaml
agent_config:
  guardrails:
    read_only: true
```

This adds a `PreToolUse` hook on `Write|Edit` that returns `permissionDecision: "deny"`.

### 5.3 Bash Command Allowlist

Each agent can customize which bash commands are permitted:

```yaml
agent_config:
  guardrails:
    allowed_commands:
      - "grep"
      - "find"
      - "git"
      - "python"
      - "ruff"
      - "mypy"
```

Commands not in the list are blocked with an explanatory message.

### 5.4 Blocked Pattern Guardrail

Block specific command patterns regardless of the base command:

```yaml
agent_config:
  guardrails:
    blocked_patterns:
      - "rm -rf"
      - "sudo"
      - "chmod 777"
      - "> /dev/"
      - "curl.*| bash"
      - "eval("
```

### 5.5 File Path Guardrail

Restrict file operations to specific directories:

```yaml
agent_config:
  guardrails:
    allowed_paths:
      - "./src/**"
      - "./tests/**"
      - "./docs/**"
    blocked_paths:
      - ".env*"
      - "*.key"
      - "*.pem"
      - ".ssh/**"
```

Implementation via `PreToolUse` hook on `Read|Write|Edit`:

```python
import fnmatch

async def file_path_guardrail(input_data, tool_use_id, context):
    """Enforce file path restrictions."""
    tool_name = input_data.get("tool_name", "")
    if tool_name not in ("Read", "Write", "Edit"):
        return {}

    file_path = input_data.get("tool_input", {}).get("file_path", "")

    # Check blocked paths
    for pattern in BLOCKED_PATHS:
        if fnmatch.fnmatch(file_path, pattern):
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PreToolUse",
                    "permissionDecision": "deny",
                    "permissionDecisionReason": (
                        f"Access to '{file_path}' is blocked by guardrail "
                        f"(matched pattern: {pattern})"
                    ),
                }
            }

    # Check allowed paths (if configured)
    if ALLOWED_PATHS:
        if not any(fnmatch.fnmatch(file_path, p) for p in ALLOWED_PATHS):
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PreToolUse",
                    "permissionDecision": "deny",
                    "permissionDecisionReason": (
                        f"Access to '{file_path}' not in allowed paths: "
                        f"{ALLOWED_PATHS}"
                    ),
                }
            }

    return {}
```

### 5.6 Human-in-the-Loop Gate

For high-stakes operations that require human approval:

```yaml
agent_config:
  guardrails:
    hil_gates:
      - trigger: "deploy"
        description: "Production deployment requires human approval"
      - trigger: "database_migration"
        description: "Database schema changes require human review"
      - trigger: "delete_data"
        description: "Data deletion requires explicit confirmation"
```

Implementation returns `permissionDecision: "ask"` which prompts the user:

```python
async def hil_gate_hook(input_data, tool_use_id, context):
    """Human-in-the-loop gate for high-stakes operations."""
    command = input_data.get("tool_input", {}).get("command", "")

    for gate in HIL_GATES:
        if gate["trigger"] in command.lower():
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PreToolUse",
                    "permissionDecision": "ask",
                    "permissionDecisionReason": gate["description"],
                }
            }
    return {}
```

| Agent Type | read_only | bash_allowlist | file_paths | hil_gates |
|---|---|---|---|---|
| Code Reviewer | Yes | linters + git | src, tests | None |
| Coding Agent | No | Full dev set | Project dir | deploy, db migration |

## 6. Schema Extension: agent_config v2

### 6.1 Backward Compatibility

The current `agent_config` schema (in `src/core/types.ts`) has four fields:

```typescript
// Current schema (v1) -- from code-reviewer persona
export interface AgentConfig {
  description?: string;
  prompt_file?: string;
  model?: AgentModelOption;  // 'haiku' | 'sonnet' | 'opus' | 'inherit'
  tools?: AgentToolConfig;
}

export interface AgentToolConfig {
  groups?: string[];
  additional?: string[];
  exclude?: string[];
}
```

The v2 extension adds new optional fields. **All new fields are optional**, so existing Tier 3 personas with `agent_config` (like code-reviewer) continue to work without changes.

### 6.2 Extended Schema (v2)

```typescript
// Extended schema (v2) -- backward compatible with v1
export type AgentModelOption = 'haiku' | 'sonnet' | 'opus' | 'inherit';
export type AgentTier = 1 | 2 | 3;

export interface AgentConfig {
  // === v1 fields (unchanged) ===
  /** Routing description for orchestrator delegation */
  description?: string;
  /** Path to system prompt markdown file, relative to the agent/prompts directory */
  prompt_file?: string;
  /** Default model tier for this agent */
  model?: AgentModelOption;
  /** Tool configuration for this agent */
  tools?: AgentToolConfig;

  // === v2 fields (new, all optional) ===
  /** Agent tier: 1 (autonomous), 2 (MCP server), 3 (prompt template). Default: 3 */
  tier?: AgentTier;
  /** Maximum conversation turns before the agent stops. Default: 200 */
  max_turns?: number;
  /** Guardrail configuration */
  guardrails?: AgentGuardrails;
  /** Sub-agent definitions for delegation */
  subagents?: Record<string, SubagentConfig>;
  /** Human-in-the-loop gate definitions */
  hil_gates?: HilGate[];
  /** Additional MCP server configurations */
  mcp_servers?: Record<string, McpServerConfig>;
  /** Permission mode: 'acceptEdits' | 'bypassPermissions' | 'manual'. Default: 'acceptEdits' */
  permission_mode?: string;
  /** Enable extended thinking. Default: false */
  thinking?: boolean | { type: 'adaptive' };
  /** Effort level: 'low' | 'medium' | 'high'. Default: 'high' */
  effort?: string;
}

export interface AgentToolConfig {
  /** Named tool groups to include (e.g., code_review, research, coding) */
  groups?: string[];
  /** Individual tool names to add beyond group membership */
  additional?: string[];
  /** Individual tool names to remove from the resolved set */
  exclude?: string[];
}

export interface AgentGuardrails {
  /** Agent is read-only: blocks Write and Edit tools */
  read_only?: boolean;
  /** Bash commands allowed (allowlist). Empty = use defaults */
  allowed_commands?: string[];
  /** Command patterns to block regardless of base command */
  blocked_patterns?: string[];
  /** File path glob patterns to allow */
  allowed_paths?: string[];
  /** File path glob patterns to block */
  blocked_paths?: string[];
  /** Maximum file size in KB for Read operations */
  max_file_size_kb?: number;
}

export interface SubagentConfig {
  /** Routing description for when to use this subagent */
  description: string;
  /** System prompt for the subagent (inline or file path) */
  prompt?: string;
  /** Tool configuration (same structure as parent) */
  tools?: AgentToolConfig;
  /** Model override for this subagent */
  model?: AgentModelOption;
}

export interface HilGate {
  /** Trigger keyword or pattern */
  trigger: string;
  /** Human-readable description shown during approval prompt */
  description: string;
  /** Severity: 'info' | 'warning' | 'critical'. Default: 'warning' */
  severity?: string;
}

export interface McpServerConfig {
  /** Server transport type */
  type?: 'stdio' | 'http';
  /** Command to run (for stdio) */
  command?: string;
  /** Arguments (for stdio) */
  args?: string[];
  /** URL (for http) */
  url?: string;
  /** Headers (for http) */
  headers?: Record<string, string>;
}
```

```python
from academy_runtime import load_agent_definition

agents = {
    "security-auditor": load_agent_definition("security-auditor"),
}
```

## Summary of Decisions

1. **Tier 1 agents are Python-only** (Claude Agent SDK is Python/TypeScript; yce-harness precedent is Python)
2. **persona YAML remains the single source of truth** -- `agent_config` extends it, doesn't replace it
3. **Tool groups are a shared catalog** -- defined once, composed by all agents
4. **Guardrails ship by default** -- every Tier 1 agent gets bash allowlisting and persona boundary checks
5. **Memory uses the `.codebase_learnings.json` pattern** from yce-harness for ecosystem consistency
6. **Subagents are single-depth** -- this is a hard SDK constraint, not a design choice
7. **The schema extension is backward compatible** -- all new fields are optional
8. **The CLI generates a running agent** -- not just boilerplate; `main.py` works immediately after scaffolding
